1. PROJECT OVERVIEW
================================================================================
NexSport ("Your Game, Your Team") is a community sports matchmaking app.
Users create/join local match rooms, get auto-balanced teams (zig-zag
algorithm), chat within rooms, give post-match feedback, and view a
performance dashboard with an AI coach.

Built with the TanStack ecosystem (React + Router + Start + Query) on Vite,
using SQLite for persistence and Tailwind v4 + shadcn/ui for UI.

5. SERVER FUNCTIONS (TanStack Start)
================================================================================
Library: @tanstack/react-start createServerFn
Files: src/server/*.ts  (auth.ts, rooms.ts, chat.ts, feedback.ts)
These are RPC-style functions that run ONLY on the server and call the DB.

How they work:
  - createServerFn({ method: "POST" }).validator(fn).handler(async ({data}) => {...})
  - Client imports them directly and calls listRoomsFn({ data: {...} }).
  - The framework compiles them into safe client calls (hashed RPC endpoints).
  - Protected by CSRF middleware (see src/start.ts createCsrfMiddleware).

Security:
  - importProtection denies **/server/** in client env EXCEPT these files.
  - CSRF filter applies to handlerType === "serverFn".
  - Server-side validation via .validator() and Drizzle eq/where.

6. DATABASE (SQLite + Drizzle ORM)
================================================================================
Database file: nexsport.db (in project root, created at runtime).
ORM: drizzle-orm (^? via bun.lock) + drizzle-kit (^0.31.10).
Driver: better-sqlite3 (synchronous, via src/db/client.ts).

Core DB files:
  src/db/client.ts     -> opens SQLite, sets WAL + foreign_keys, exports db.
  src/db/schema.ts     -> table definitions (users, rooms, room_members,
                          messages, feedback).
  src/db/migrate.ts    -> runs migrations.
  src/db/seed.ts       -> seeds demo data (demo user + 5 rooms + chat).
  src/db/verify.ts     -> verification helpers.
  drizzle.config.ts    -> drizzle-kit config (schema, out, dialect sqlite,
                          dbCredentials.url = ./nexsport.db).

Tables (schema.ts):
  users(id, name, email unique, password_hash, city, elo, created_at)
rooms(id, sport, venue, city, distance_km, time, slots, filled, avg_elo,
        skill, host, host_user_id, status [open|filling|closed],
        description, lat, lng, created_at)
        (lat/lng = real GPS coordinates captured from the creator's browser)
  room_members(id, room_id FK->rooms, user_id FK->users nullable, name,
               skill, joined_at)
  messages(id, room_id FK->rooms, author, initials, text, time, user_id,
           is_me bool, system bool, created_at)
  feedback(id, room_id FK->rooms, user_id FK->users nullable, sport, venue,
           date, skill, fairness int, teammates int, performance int,
           result [Win|Loss|Draw], comment, created_at)

Drizzle Studio (browser DB viewer):
  npx drizzle-kit studio --port 4983  -> opens https://local.drizzle.studio
  (already running in the dev environment)

7. STATE & DATA FETCHING (TanStack Query)
================================================================================
Library: @tanstack/react-query (^5.101.1)
Used to fetch/cache server-function results and keep UI in sync.

Pattern in pages:
  const { data, isLoading } = useQuery({
    queryKey: ["rooms"],                       // unique key
    queryFn: () => listRoomsFn(),              // server fn
  });
  const queryClient = useQueryClient();
  await queryClient.invalidateQueries({ queryKey: ["rooms"] }); // refetch

Key query keys used:
  ["rooms"]                       -> list of rooms
  ["rooms", roomId]               -> single room
  ["messages", roomId]            -> room chat messages
  ["feedback", userId]            -> user's feedback

13. AUTHENTICATION (localStorage + bcrypt)
================================================================================
Server-side (src/server/auth.ts):
  - loginFn: finds user by email, bcrypt.compare(password, hash).
  - signupFn: bcrypt.hash(password, 10), inserts user, guards duplicate email.
Client-side (src/lib/auth.tsx):
  - AuthProvider context holds user state.
  - Persists session in localStorage under key "nexsport_auth".
  - login()/signup() call server fns, then applyUser() saves to localStorage.
  - logout() clears localStorage.
  - useRequireAuth() hook: redirects to "/" + opens login modal if unauthenticated.
Protected routes: /rooms, /dashboard, /profile, /leaderboard.

NOTE: This is a prototype session (localStorage), NOT a secure cookie/JWT.
For production, replace with HttpOnly cookies + sessions.
